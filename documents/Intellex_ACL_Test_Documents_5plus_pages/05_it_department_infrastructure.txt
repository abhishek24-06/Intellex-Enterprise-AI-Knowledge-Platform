# IT Department Infrastructure Operations

**Visibility:** DEPARTMENT: IT

**ACL Test Marker:** `DEPT-IT-05-EPSILON`


## 1. Infrastructure Scope

This document describes internal infrastructure operations for the IT department. It covers service health, deployment environments, monitoring, configuration changes, incident records, and recovery validation.


## 2. Service Inventory

Infrastructure records should identify important services, dependencies, owners, and operational state. The inventory provides context during incidents and reduces the risk of changing the wrong component.


### Reference Table

| Field | Example | Purpose |
|---|---|---|
| Owner | Assigned employee | Accountability |
| Status | In progress | Current state |
| Priority | High | Ordering work |
| Review | Required | Quality control |


## 3. Health Checks

Routine health checks should verify application availability, database connectivity, queue status, monitoring state, and recent deployment activity. Results should be recorded when they are relevant to an operational decision.


## 4. Deployment

A deployment should identify the version, target, owner, validation checks, and rollback method. A successful deployment is not merely the absence of an error; the operator should confirm expected behavior.


## 5. Configuration Management

Configuration changes should be documented with the reason, old and new values where appropriate, affected service, and verification result. Sensitive credentials should never be copied into ordinary documentation.


## 6. Monitoring

Monitoring alerts are signals rather than complete diagnoses. Operators correlate alerts with recent changes, service logs, and dependency health before deciding on mitigation.


## 7. Incident Response

An infrastructure incident record should contain an identifier, affected service, start time, impact, mitigation, owner, and final resolution.
