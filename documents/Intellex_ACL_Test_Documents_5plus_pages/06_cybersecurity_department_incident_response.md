# Cybersecurity Department Incident Response

**Visibility:** DEPARTMENT: Cybersecurity

**ACL Test Marker:** `DEPT-CYBER-06-ZETA`


## 1. Security Incident Scope

This procedure defines the response workflow for the Cybersecurity department. It addresses identification, classification, containment, investigation, remediation, evidence handling, and post-incident review.


## 2. Identification

An event becomes an incident when available evidence indicates that a security control, system, identity, or information asset may have been compromised or exposed. Initial classification should remain evidence-based.

## 3. Severity

Severity can consider impact, scope, affected assets, confidence, and urgency. Classification should be revisited as evidence changes.


## 4. Containment

Containment aims to limit additional impact while preserving enough evidence for investigation. Actions should be recorded with timestamps and owners.


## 5. Investigation

Investigation connects alerts, logs, identities, system behavior, and timelines. Analysts should distinguish observed evidence from hypotheses about root cause.


## 6. Evidence Handling

Evidence should be preserved in a manner that maintains traceability. A record should identify the source, collection time, handler, and relevant integrity information.


## 7. Remediation

Remediation removes the cause or reduces the likelihood of recurrence. Changes should be validated after implementation.


## 8. Post-Incident Review

A review captures what happened, what worked, what failed, and what should change. Action items should have owners and target dates.


## 9. Example Structure

A simplified incident object can be represented as a code excerpt.
